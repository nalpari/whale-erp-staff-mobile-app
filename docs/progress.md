## 2. 계획 항목별 상태

### 네이티브 껍데기 (이 저장소)

| 항목 | 상태 | 근거 · 남은 일 |
| --- | --- | --- |
| 원격 URL 로드 · 환경 분리 | ✅ | `--dart-define=WEB_URL`. dev 기본값 |
| 외부 링크 | ✅ | `isInApp` + `url_launcher`, 단위 테스트 있음 |
| Android 뒤로 가기 | ✅ | 웹에 열린 `<dialog>`(바텀시트)가 있으면 가장 나중에 연 것부터 닫고(연 순서는 페이지 시작 때 심는 스크립트가 남김, DOM 순서가 아님), 없으면 웹 히스토리 → 앱 종료(2026-11-23). 웹 변경 없이 앱이 `cancel` 이벤트를 보내 웹 시트의 onCancel이 닫는다. 에뮬레이터에서 시트 2개 → 뒤로 가기 두 번에 하나씩 닫히고 세 번째에 앱 종료를 확인. dev `/design` 견본의 실제 웹 `BottomSheet`(「어디에서 근무하시나요?」)도 뒤로 가기로 닫히고 페이지는 그대로인 것을 확인(React onCancel 경로) |
| 오프라인 · 오류 화면 | ✅ | `_ErrorView` + 다시 시도 |
| 스플래시 · 아이콘 · 상태바 | 🟡 | 확정 시안(후보 A)으로 이미지 교체 완료. 남은 일: 에뮬레이터 · 실기기에서 두 단계 스플래시 이어짐과 남보라 위 흰 상태바 아이콘(`SystemUiOverlayStyle.light`)이 잘 보이는지 확인 |
| 키보드 | 🟡 | `adjustResize`는 있다. 하단 sticky Dock이 가리는지 실기기 확인이 남았다 |
| **위치 권한** | 🟡 | Android `ACCESS_FINE_LOCATION` · `ACCESS_COARSE_LOCATION`, iOS `NSLocationWhenInUseUsageDescription`(2026-11-20). 웹이 `navigator.geolocation`을 부르면 Android는 `onGeolocationPermissionsShowPrompt`에서 웹 주소와 같은 https 출처만 OS 권한(`geolocator`)을 물어 허락한다(`retain: false`, 페이지를 새로 불러올 때마다 OS 권한 재확인). 권한 확인 오류 · 60초 무응답은 거부하고 「다시 시도」 안내를 띄운다(60초에는 사용자가 권한 창을 보고 고민하는 시간도 들어간다. 알려진 한계). Android에서 이미 「대략적 위치」로 허락돼 있으면 앱을 켠 동안 한 번 정확한 위치로 바꿀지 다시 묻고(방금 창에서 대략적을 골랐으면 그 자리에서는 다시 묻지 않음, 재요청이 실패하면 대략적 위치 그대로), 대략적 위치 · 영구 거부 · 기기 위치 꺼짐이면 설정으로 가는 안내(SnackBar)를 띄운다. 스플래시 중에 나온 안내는 첫 페이지가 그려진 뒤 띄운다. 에뮬레이터에서 확인 창이 OS 것 하나만 뜨고, 허용하면 좌표, 거부하면 웹이 `PERMISSION_DENIED`를 받는 것을 확인. 남은 일: iOS는 이 콜백이 없어 출처 검사가 적용되지 않고(WKWebView가 직접 처리), OS 권한 창과 사이트 확인 창이 따로 뜰 수 있다. iOS는 시뮬레이터 빌드만 확인했고 실기기에서 창이 몇 번 뜨는지 봐야 한다. 정확한 위치 재요청 창과 안내는 테스트로만 확인했고 에뮬레이터 · 실기기에서는 아직 못 봤다 |
| 위치 측정 · 조작 감지 (결정 8) | 🟡 | 앱 쪽 브리지 기능 `measureLocation`이 생겼다(2026-11-23, `lib/location_reading.dart`). 권한 확인 → 새 측정 → 좌표 · 정확도 · `mocked` · `precise`를 한 번에 돌려준다. 에뮬레이터에서 실제 위치는 `mocked: false`, 셸 테스트 제공자로 넣은 모의 위치는 `mocked: true`로 확인. 웹은 앱 안이면 이 값을 쓴다(웹 PR #90 · #91). 남은 일: 테스트 계정으로 앱 안 실제 출퇴근, iOS 모의 위치 실기기 확인 |
| 파일 받기 (급여 PDF · 계약서) | 🟡 | 앱이 받아 공유 시트로 연다(2026-11-23, `lib/file_download.dart`). 급여 PDF는 `/pay/<id>/pdf` 이동을 `shouldOverrideUrlLoading`에서 가로채(웹뷰가 열기 전) 웹 주소와 같은 출처일 때만 웹뷰 쿠키를 실어 받는다. 리다이렉트는 같은 출처나 S3 서명 주소로만 따라가고, 파일 50MB · 오류 글 64KB 상한. 계약서는 `shouldOverrideUrlLoading`에서 S3 서명 주소(https · `*.amazonaws.com` · 서명 값)로 가는 이동을 막고 쿠키 없이 받는다. 실패 글자(text/plain)는 그대로 안내. 화면(200 HTML, 로그인 등)이 오면 쿠키를 싣는 같은 출처 받기에서만 HTML이 온 최종 주소를 웹뷰에서 열고, 15초 안에 또 화면이 오면 끊고 안내한다. 그 밖의 HTML(502 등)은 실패로 안내. 시간 제한은 헤더까지 30초, 본문 15초 무응답, 쿠키 읽기 5초. 에뮬레이터에서 S3 주소 가로채기(바깥 브라우저로 안 나감 · 실패 안내)와 급여 PDF 주소 가로채기(로그인 없이 누르면 앱이 받고 로그인 화면으로)를 확인. **로그인한 실제 급여 PDF · 계약서 받기와 공유 시트는 테스트 계정이 없어 못 봤다**. 웹이 급여명세서 PDF 받기 실패를 평문 대신 명세서 상세(`/pay/<id>?download=…`)로 돌려보내게 바뀌어(웹 브랜치 `magmar`, 2026-11-24), 앱은 그 안내 화면을 웹뷰에 열고 로그인 되풀이 막기(15초)에 세지 않는다(`isPayslipFailurePage`) |
| 쿠키 유지 (자동 로그인 30일 / 7일) | 🟡 | Android는 앱이 비활성 · 화면에서 사라질 때(`AppLifecycleListener.onInactive` · `onHide`, 홈 · 앱 전환 · 최근 앱 화면. 런처에 따라 최근 앱 화면에서 inactive에서 멈추므로 거기서도 쓴다. 밀어 끄는 동작은 따로 콜백이 없어 그 전에 쓴 것에 기댄다) `CookieManager.flush()`로 쿠키를 디스크에 쓴다(`flushCookies`, 2026-11-24). 플러그인(1.2.0-beta.3) flush는 답하지 않아 앱을 내릴 때마다 엔진에 콜백이 남았으므로, `MainActivity`의 앱 채널(`kr.co.whaleerp.staff/cookies`)로 쓰고 바로 답한다. flush는 디스크 쓰기가 끝날 때까지 부른 스레드를 막고 알림창 · 권한 창(inactive)에서도 불리므로 백그라운드 작업 큐에서 처리한다. 2초 제한, 오류 · 시간 초과는 보고만 한다. iOS는 WKWebView가 스스로 저장하고 플러그인에 flush가 없어 부르지 않는다. 에뮬레이터(Pixel 8)에서 웹뷰 개발자 도구로 시험 쿠키를 넣고 확인: 홈으로 내린 뒤 강제 종료하면 이 빌드는 쿠키가 남고(최근 앱 화면을 연 뒤 강제 종료해도 남음, PR #8 리뷰 반영 뒤 확인), main 빌드(flush 없음)와 홈 없이 바로 강제 종료하면 사라졌다. 남은 일: 테스트 계정으로 실제 로그인 유지 확인(Android · iOS 실기기) |
| 기기 식별자 | 🟡 | 브리지 기능 `deviceId`(2026-11-24). Android `ANDROID_ID` · iOS `identifierForVendor`에 앞말을 붙여 SHA-256 으로 바꾼 64자 16진수만 웹에 넘긴다(원래 값은 앱 밖으로 안 나감, 창수 결정). 에뮬레이터에서 64자 값이 오는 것 확인, iOS 는 시뮬레이터 빌드만. 웹 로그인이 앱 안에서는 이 값을 쓰게 하는 작업은 웹 브랜치 `magmar`. 남은 일: Google Play 데이터 보안 양식에 「기기 ID」 적기 |
| 딥링크 (`/invite` · `/password-reset/link` · `/affiliations`) | ❌ | intent-filter · Associated Domains가 없다. 알림톡 버튼(카카오톡 인앱 브라우저)에서 앱이 뜨는지도 실기기로 봐야 한다. 번들 ID를 확정해야 시작할 수 있다 |
| 푸시 (FCM · APNs) | ❌ | api 팀과 토큰 등록 API 협의가 먼저다. 무엇을 언제 보낼지(알림 4가지 · 템플릿 5종 · 수신 설정 4묶음 · 누르면 갈 화면)는 명세 보관소 알림 정책(NTF)에 정해져 있다. 새로 정할 것: 토큰을 로그아웃 · 기기 변경 때 지우는 규칙, 휴대전화 알림 권한(Android 13+ · iOS)을 언제 물을지, 1차 동안 쌓인 「발송 대기」 푸시를 버릴지, 푸시가 붙은 뒤 알림톡 · 메일 채널을 다시 볼지(옵시디언 「출시-협의-안건」 4번) |
| 강제 업데이트 | ❌ | api 팀과 최소 앱 버전 값 협의가 먼저다 |
| 당겨서 새로고침 | 🟡 | 네이티브 `PullToRefreshController`를 켰다(계획은 웹에서 오버스크롤을 끄는 것이었다). 서명 패드(`touch-none`)가 화면에 있는 동안 미리 당겨서 새로고침을 끄고(누르는 순간 끄면 맨 위에서 빠르게 그은 첫 획을 새로고침이 먼저 가로챌 수 있어서), `touch-action: none`인 곳을 누르는 동안에도 끄며 둘 다 아니면 다시 켠다(`pullToRefreshGuardScript` · 앱 안쪽 브리지 기능 `pullToRefresh`, 새 문서가 시작될 때(`onLoadStart`) 다시 켬 — 로딩이 끝날 때(`onLoadStop`) 켜면 이미지 로딩 중 시작한 서명 보호가 풀림, 2026-11-24). 웹은 고치지 않는다. 에뮬레이터에서 터치 시작 · 끝 이벤트가 오는 것은 확인했지만, adb 입력으로는 고치기 전 빌드에서도 당겨서 새로고침이 일어나지 않아 막히는지 자체는 확인하지 못했다. 남은 일: 실기기에서 계약서 서명 화면으로 확인 |
| 릴리즈 서명 · iOS 프로비저닝 | 🟡 | Android: `android/key.properties`(저장소에 넣지 않음, 형식은 `android/key.properties.example`)가 있으면 그 키로 release를 서명하고, 없으면 지금처럼 debug 키로 서명한다(2026-11-24). 시험 키로 빌드해 서명자가 바뀌는 것과, 파일이 없을 때 debug 키로 남는 것을 `apksigner`로 확인. 남은 일: 실제 업로드 키를 만들고 보관할 사람(계획 결정 16), Play 앱 서명 등록. iOS는 시뮬레이터 빌드 · 실행만 확인했다(2026-11-20, Xcode 27.2). 실기기 서명 · 프로비저닝은 회사 Apple 계정이 생긴 뒤 |
