## What this is

A Flutter (Android + iOS only) WebView shell for the staff mobile web app `whale-erp-staff` (Next.js, sibling repo `../whale-erp-staff`). The app itself has almost no UI: it loads the web app full screen and adds native glue (back button, external links, pull-to-refresh, error/retry, splash). Bundle ID `kr.co.whaleerp.staff`, display name `WHALEERP`, portrait only.

## Commands

```bash

flutter analyze
```

`WEB_URL` defaults to the dev URL (`https://staff-dev.whaleerp.co.kr`) in `lib/main.dart`; there is a TODO to switch the default to prod once the prod URL exists. dev/prod are one app ID switched by the define, not flavors.

Local Android tooling on this machine: SDK at `/opt/homebrew/share/android-commandlinetools` (adb/emulator are not on PATH; use `platform-tools/adb`, `emulator/emulator`). AVD `whale_pixel` (Pixel 7, Android 16) lives in `~/.android/avd`. `avdmanager` from the Homebrew `cmdline-tools/latest` (v22) cannot create AVDs for the API 36 image; use `cmdline-tools/latest-2` (v23). `flutter run` here has failed to attach DDS after launch; the installed app still runs.

## Architecture

Everything lives in `lib/main.dart`.

- `isInApp(uri, base)` is the navigation rule: same host as `WEB_URL` over http(s), or webview-internal schemes (`about`, `data`, `blob`, `javascript`), stay in the webview. Everything else (other hosts, `tel:`, `mailto:`) is cancelled in `shouldOverrideUrlLoading` and opened with `url_launcher` externally. It is the one unit-tested function (`test/widget_test.dart`); the webview itself is not testable in widget tests.
- `WebScreen` wraps the `InAppWebView`: `PopScope` maps Android back to webview history, then `SystemNavigator.pop()`. A main-frame load error (except `CANCELLED`) shows `_ErrorView`. User-Agent gets `WhaleERPStaffApp` appended so the web app can detect the shell.

### Two-stage splash (the subtle part)

The OS splash (generated by `flutter_native_splash`) is static, so `SplashOverlay` draws an identical screen in Flutter on top of the webview while the first page loads, then fades out. The handoff only looks seamless if these invariants hold:

- `splashColor`, `splashLogo`, `splashLogoSize` in `main.dart` must match the `flutter_native_splash` block in `pubspec.yaml`. The 720px `assets/splash_logo.png` is treated as 4x by the package, hence 180dp. The overlay sits outside `SafeArea` so it is centered on the full screen like the OS splash.
- `main()` calls `deferFirstFrame()` and `SplashOverlay` calls `allowFirstFrame()` only after `precacheImage`, so the first Flutter frame never shows the background without the whale.
- `MainActivity.kt` removes the Android 12+ system splash with no exit animation (`setOnExitAnimationListener { it.remove() }`); the default animation fades the icon out first and breaks the handoff.
- The overlay hides only after `onLoadStop` plus two `requestAnimationFrame`s inside the page; `onLoadStop` alone fires before the page paints and exposes a blank white webview.
- The loading ring is added to the tree only after the webview is attached (`onWebViewCreated` + `endOfFrame`). Rendering it earlier (even at opacity 0) produced one-frame opaque flashes / disappearing frames when the platform view joined composition on the emulator.
- The ring is hidden when `MediaQuery.disableAnimations` is true. On Android Flutter derives that from `transition_animation_scale`, not `animator_duration_scale`.
- `AnnotatedRegion` sets light status-bar icons over the dark overlay and dark icons over the web content.

### Image assets

All splash/icon images derive from `assets/hf_20260820_080200_343cd9fa-537d-46c7-b869-1d87f4104b18.png` (2048px, whale `#f7fe57` on `#0a0a0a`, no alpha). The derived PNGs were produced with one-off Python/PIL scripts that are not in the repo: alpha from color distance to `#0a0a0a`, RGB set to `#f7fe57`, whale cropped to its bounding box and centered.

| File | Use | Geometry |
| --- | --- | --- |
| `splash_logo.png` | OS splash + Flutter overlay | 720px, whale diagonal = 720px |
| `splash_logo_android12.png` | Android 12+ splash icon | 1152px canvas, whale within the 768px masked circle |
| `app_icon.png` | iOS icon, Android ≤7 legacy icon | 1024px, background filled, whale 70% width |
| `app_icon_foreground.png` | Android adaptive foreground + monochrome | 1024px transparent, whale 50% width (diagonal ≈ 65dp of 108dp) |

Because the foreground PNG already includes the 108dp safe-zone padding, `adaptive_icon_foreground_inset: 0` disables the package's default 16% inset.

## Dependency pins

`flutter_inappwebview` is pinned to `6.2.0-beta.3`: the 6.1.5 stable Android implementation uses `proguard-android.txt`, which AGP 9 (used by this template) rejects. Overriding only `flutter_inappwebview_android` breaks the Windows implementation via the shared platform interface, so the whole family is on the beta. Move to `^6.2.0` once stable ships.
